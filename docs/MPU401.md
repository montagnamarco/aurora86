# MPU-401 UART foundation

The optional `mpu401-uart` sound card exposes a standalone two-port MIDI
interface compatible with the UART subset documented by early-1990s
Creative and Logitech adapters. It does not implement the original MPU's
intelligent sequencer. Default hardware remains unchanged.

Add an entry to `hardware.sound` with explicit resources:

```json
{"card": "mpu401-uart", "port": "330", "irq": 9}
```

The same list may retain its `sb16` entry. The MPU is separate from the
Sound Blaster's DSP, mixer, IRQ and OPL3. It has no DMA, game port or ISA
Plug and Play identity. Ports cannot overlap another fitted card. IRQ2 is
rejected because it is the AT cascade; configure IRQ9 explicitly.

Base+0 carries data; base+1 reads status and accepts commands. Status bit
7 is clear while an acknowledgement is readable. Bit 6 is clear while the
eight-byte transmit FIFO has room. FFh at the command port resets the
interface and replies FEh; 3Fh enters UART and replies FEh. Reset clears
old replies and unsent data. Repeated 3Fh in UART and unsupported commands
are ignored. FFh at the data port is ordinary MIDI stream data.

Reading an acknowledgement releases its IRQ and reasserts it if another
reply remains. There are no transmit-completion interrupts or MIDI input.
Power reset produces no unsolicited reply. Empty data reads return FFh;
unused status bits read zero. Command completion and IRQ reassertion are
instantaneous model policies, with no serial clock or measured reset delay.

`Machine.ConnectMidi(IMidiSink)` attaches a raw-byte output. A sink's
`TryWriteByte` accepts exactly one byte or returns false without accepting
anything. Calls must not block. Rejected bytes stay in the guest FIFO and
are retried when devices advance. A write while the FIFO is full discards
the new byte, then retries the older bytes; drivers must poll bit 6.

The machine owns disposal of sinks attached through `ConnectMidi`.
Replacement resets both streams and closes the detached sink. The device's
lower-level `SetSink` API changes the stream without taking disposal
ownership. Neither replacement nor snapshot restoration drains the FIFO.

The default null sink accepts bytes silently. On Windows, `WinMmMidiSink`
can send output to an explicitly selected host endpoint. Run the SDL front
end with `--list-midi` to enumerate IDs without opening a device, then add
the top-level setting `"midiOutput": { "deviceId": 0 }` to `vm.json`, using
the desired enumerated ID. The hardware sound list must also contain an
`mpu401-uart` card at port `330`, IRQ 9. Loading a machine opens host output
only after its guest devices and media have been validated. Other operating
systems reject an enabled WinMM output; leaving the setting absent keeps
the existing silent sink. There is no bundled synthesizer or SoundFont.

The native worker accepts at most 4096 queued bytes and owns one long-message
header at a time. The guest never calls WinMM directly. Reset discards queued
bytes and parser state immediately, then the worker silences the endpoint.
An interrupted native SysEx requires a separate F7 long message after the
old buffer has been returned and unprepared. A reset can race with the one
native call already reserved by the worker; it cannot undo bytes already
delivered. Real-time messages arriving during a pending native SysEx wait
behind it, so precise serial timing is not promised.

Driver errors stop acceptance and appear in the GUI status or SDL console.
Oversized SysEx counts are also visible there. Native NOTREADY is retried
for at most 500 ms; normal completion has a 30-second deadline. Startup and
disposal wait at most five seconds each. If a driver fails to return memory,
the worker retains its handle and buffer until safe cleanup succeeds, and
the endpoint cannot be reopened through the adapter in the meantime.
`Completion` reports actual cleanup, even when `Dispose` has timed out.
Replace a failed sink after cleanup to reopen output.

`MidiMessageFramer` supplies the platform-independent host framing layer.
It preserves channel running status and interleaved real-time messages,
and emits complete short messages or SysEx spans. SysEx is limited to
65536 bytes including F0/F7; an overflow discards that message and increments
`DroppedSysExCount`. A new non-real-time status implicitly ends a buffered
SysEx with a synthetic F7 before that status is processed. Stream reset
discards incomplete messages and running status, but keeps the lifetime
drop count. The framer is synchronous, single-threaded and non-reentrant;
a throwing sink requires reset before any more bytes are supplied.

The `MPU4` version-one snapshot is 14 bytes: fixed port and IRQ, UART mode,
acknowledgement count, and up to eight unaccepted transmit bytes with zero
padding. Malformed payloads and mismatched resources fail before machine
RAM changes. The target keeps its sink, whose partial stream is reset.
Already accepted output is not replayed. External synthesizer voices and
exact audible continuation are not snapshot state; the host adapter
must discard orphaned data until a fresh MIDI status reestablishes framing.

The selected compatibility profile is grounded in the
[Creative Sound Blaster Hardware Programming Guide](https://www.phatcode.net/res/243/files/sbhwpg.pdf)
(chapter 5) and the
[Logitech SoundMan Wave Technical Reference](https://www.bitsavers.org/pdf/logitech/SoundMan_Wave_Technical_Reference_Mar94.pdf)
(pages 27–30). No physical Roland oracle was used.
