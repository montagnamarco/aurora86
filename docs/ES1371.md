# Ensoniq AudioPCI ES1371

The optional `es1371-pci` card models Ensoniq's 1997 AudioPCI ES1371: a small
bus-mastering DMA engine (two playback channels, DAC1 and DAC2, and one
recording channel, ADC) sitting in front of a generic AC'97 codec. Select it
in `vm.json`'s `hardware.sound` list, alongside or instead of the Sound
Blaster:

```json
{"card": "es1371-pci", "port": "C400"}
```

## PCI identity and placement

1274:1371, class 040100h (multimedia audio device), revision 02h (the
earliest plain-ES1371 stepping the spec's revision table names -- this model
is neither an ES1373 nor a "B" step). BAR0 is a 64-byte I/O window, the real
chip's own size; there is no memory BAR. PCI INTA is routed by the
motherboard's own PIRQ rotation.

The card occupies PCI device 2, function 0 -- the same address the primary
UHCI controller uses by default on an i430FX board. This is a fixed slot, not
a scanned "first free" one, for the same reason the RTL8139's own slot is
fixed: this board's PIRQ rotation only ever routes PCI devices 2-5, four
slots in total, and with the always-present S3 video card fixed at device 4
and a network card, if any, fixed at device 5, there is no fifth number to
hand a sound card unconditionally. Device 2 is free whenever no USB card is
fitted at all, and on an i430TX board even when one is (PIIX4 integrates the
primary UHCI controller into its own southbridge function, 00:01.2, instead
of this slot); it collides only with an *explicitly* configured `uhci-piix`
card on an i430FX machine, which `Es1371Card.Attach` refuses with a clear
`InvalidOperationException` rather than letting the two PCI functions
silently contend for the same address.

## Register file (BAR0, 64 bytes)

| Off | Name | Notes |
|---|---|---|
| 00h | CONTROL | ADC_STOP, DAC1/DAC2/ADC enable, UART/joystick/codec enable, SERR disable; bits 9:8 select DAC1's own fixed rate (5512/11025/22050/44100 Hz) -- a position this project chose itself, since the ES1371 datasheet's PDF text layer would not extract |
| 04h | STATUS | read-only, computed from the three channels' own pending bits |
| 08h | UART | out of scope: plain storage |
| 0Ch | MEMPAGE | low nibble 0Ch selects DAC1's own frame/size at 30h/34h, 0Dh selects the ADC's |
| 10h | SRC | the sample-rate converter's indirect RAM port |
| 14h | CODEC | the indirect AC'97 port |
| 18h | LEGACY | out of scope: plain storage |
| 1Ch | SPDIF | out of scope (ES1373 only): plain storage |
| 20h | SERIAL | per-channel mode, pause, loop-select and interrupt-enable |
| 24h/28h/2Ch | DAC1/DAC2/ADC COUNT | 31:16 current countdown (read-only), 15:0 reload, in sample frames minus one |
| 30h/34h | DAC1 or ADC FRAME/SIZE, by MEMPAGE | FRAME is the guest physical base; SIZE is 31:16 current position, 15:0 ring length minus one, both in 32-bit words |
| 38h/3Ch | DAC2 FRAME/SIZE | not paged |

## Units and the DMA engine

FRAME and SIZE describe the ring a channel walks in guest RAM, in 32-bit
words; COUNT is an independent period counter, in sample frames (whose byte
width depends on the channel's own format), that reloads and raises the
channel's STATUS bit at zero. The two are deliberately decoupled: a driver
sets SIZE to the whole buffer and COUNT to half of it, in sample frames, to
get one interrupt every half buffer while the ring itself keeps running.
SERIAL's own per-channel LOOP_SEL bit decides what happens when the ring
position reaches its own end: clear, it wraps and playback continues
(interrupts keep firing every period); set, the channel halts exactly there,
consuming no further frames until the driver reprograms and re-enables it.

Each DMA channel keeps an internal byte cursor into the 32-bit word it is
currently working through, plus (for DAC1/DAC2) a cached copy of the last
word fetched -- the same word can hold more than one sample frame (four for
8-bit mono, two for 8-bit stereo or 16-bit mono, one for 16-bit stereo), and
a fresh word is only fetched once the previous one is fully consumed.

## Sample-rate converter

DAC1 keeps ES1370's own fixed four-rate clock, selected from CONTROL. DAC2
and the ADC are driven by a 128-word RAM a driver programs indirectly
through the SRC port at 10h: writing the port with WE set stores at the
addressed word; writing it with WE clear stages a read, available at once
since BUSY always reads 0 (there is no wait to model). The rate itself is
decoded from two RAM words per channel (INT_REGS at the channel's own base
+1, VFREQ_FRAC at +3) with the formula:

```
freq = ((INT_REGS & FC00h) << 5) | VFREQ_FRAC
rate = round(freq * 3000 / 65536)
```

the exact inverse of the driver's own encoding formula, so a rate programmed
through the real driver's own arithmetic decodes back within rounding.

## Interrupt acknowledgement

Unlike the RTL8139's ISR, STATUS has no write-1-to-clear: a channel's
pending bit clears the instant its own SERIAL interrupt-enable bit goes from
1 to 0. A driver acknowledges by writing SERIAL with that bit cleared, then
writing it back to keep receiving future interrupts -- re-enabling alone
never resurrects an already-cleared condition, only a fresh period reaching
zero does.

## AC'97 codec

Reached only through the indirect CODEC port at 14h (RDY always 1, WIP
always 0 -- there is no wait to model). `Ac97Codec` is a generic AC'97 2.1
register file: writing register 00h reloads every default regardless of the
value; register 28h (Extended Audio ID) is fixed at 0001h, advertising
variable rate audio; register 2Ah's bit 0 enables it, and only then do the
front DAC (2Ch) and ADC (32h) rate registers hold what was written rather
than the fixed 48000 Hz (0xBB80) default. The vendor ID pair (7Ch/7Eh,
8384h/7609h, SigmaTel STAC9721) is cosmetic and uncertain, kept only because
an all-zero or all-one identity is itself a plausible "no codec" signal some
drivers act on. Every other register is plain read/write storage.

## Audio path

DAC1 and DAC2 are two independent producers, each resampled by simple
repetition (the same technique `SoundBlaster16` already uses for its own
DSP-to-mixer rate conversion) into its own small ring at a fixed 48000 Hz --
the rate `Es1371.ReadSamples` reports to `AudioMixer` as its
`NativeSampleRate`, decoupled from whatever DAC2's own programmed rate
currently is. `ReadSamples` sums the two rings and clips once, mirroring
`AudioMixer`'s own reasoning for why clipping happens at the very end: an
enabled channel with nothing yet rendered limits how many frames are
delivered (the same underrun policy the outer mixer applies to every
source), but a *disabled* channel never does -- it simply contributes
silence without holding the other one back. The ADC has no host capture: it
writes silence (0x80 for unsigned 8-bit, 0 for signed 16-bit) into its own
ring in guest RAM at the programmed rate, raising its own interrupt exactly
as a real recording would.

## Snapshot

State is captured under a new `E137` section, versioned and length-checked
through `CardCatalog.NewestSnapshotVersions`/`FixedSnapshotLengths`: CONTROL,
the three channels' own pending STATUS bits, MEMPAGE, the UART/LEGACY/SPDIF
scratch registers, SERIAL, the SRC port and its 128-word RAM, the indirect
CODEC port's own last value, the embedded AC'97 register file, and each
channel's FRAME/SIZE/COUNT together with its internal byte cursor and
fractional-frame accumulators. PCI configuration (including the BAR) is
captured separately by `PciBus`; the DAC1/DAC2 output rings are host
presentation state and are not captured, exactly as `SoundBlaster16`'s own
summary explains for its equivalent ring.

## What is not modelled

The dumb UART (no intelligent mode, no FIFO debug pages), the LEGACY
register's SB/game-port bridging, the joystick port, and S/PDIF (ES1373
only) are all out of scope: nothing here interprets them beyond plain
read-back storage. PCI burst-size and FIFO-threshold timing are not modelled
either. No real Windows or Linux ES1371 driver has been run against this
card; the register contract above is what this project's own design choices
and the Linux `ens1370.c` reference establish, not a driver trace.
