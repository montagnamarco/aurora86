# x87 exception synchronization

The x87 status word records sticky exception flags separately from the
control word's masks. ES and B indicate that at least one of the six flags
is unmasked. Loading a control word can therefore make an old exception
pending without executing arithmetic. Environment loads and machine
snapshot restores reconcile these summary bits with the flags and masks.

With CR0.NE set, a pending exception raises vector 16 at the next waiting
x87 instruction, FWAIT, or an MMX instruction. The fault belongs to that
waiting instruction and does not clear the environment. FWAIT raises
device-not-available first when both MP and TS are set; EM alone does not
disable FWAIT. Ordinary x87 escapes still check EM and TS.

The handler can inspect or repair the environment using FNCLEX, FNINIT,
FNSTSW, FNSTCW, FNSTENV and FNSAVE without triggering the old exception.
FNSTENV saves the original environment, then masks the live exceptions
only after its writes succeed. FNSAVE resets the unit after its complete
save. FXSAVE and FXRSTOR do not wait for pending x87 exceptions.

Mixed MMX/XMM conversions also synchronize where the instruction requires
it. There is a specific asymmetry: CVTPI2PS checks even with a memory
source, while CVTPI2PD with a memory source does not. Ordinary XMM
arithmetic and moves are independent of pending x87 exceptions.

The implementation follows the instruction definitions and detailed SIMD
exception tables in the [Intel software developer manuals](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html).
Native restore probes also checked contradictory FCW/FSW images: summary
bits are reconstructed rather than copied blindly.

## Current boundaries

- CR0.NE clear still has no functional FERR/IGNNE/IRQ13 wiring or CPU wait
  mechanism. The emulator preserves its prior execution behavior in this
  mode; it does not synthesize a native #MF or clear the pending flags.
- For valid instructions, the selected ordering is instruction-byte fetch,
  device availability, pending #MF, then data-operand checks. Intel permits
  implementation-dependent ordering within a fault-priority class; the
  #MF/data-fault ordering here is an emulator policy, not a silicon measurement.
- Existing arithmetic does not yet detect all x87 exceptions or implement
  every masked result and stack fault. This synchronization mechanism does
  not imply full arithmetic exception support.
- Saved instruction and operand pointers remain zero. Exception handlers
  cannot yet use them to diagnose the operation that originally failed.
- Legacy save instructions retain their existing multiwrite behavior:
  a memory fault can leave a partially written image, but must not reset
  the unit or mask its exceptions before the save completes.

SSE3 includes FISTTP in all three integer widths. Conversion uses the raw
80-bit significand rather than narrowing through a host double, and checks
the signed range after truncation. Invalid masked conversions store integer
indefinite; invalid unmasked conversions neither store nor pop. Precision
still stores and pops even when unmasked, deferring #MF to the next wait.
True and pseudo-denormals set precision, not the operand-denormal flag.
Destination faults leave the conversion's flags and stack uncommitted.

Core2 and Haswell advertise SSE3; the catalog's Northwood Pentium 4 does not.
MONITOR/MWAIT remain unsupported under their separate feature bit.
