# RTL8029AS PCI Ethernet

The optional `rtl8029-pci` card models the PCI interface of Realtek's
1997 RTL8029AS around the existing DP8390/NE2000 packet engine. The default
machine still uses `ne2000-isa`. Select the PCI card in the existing
`hardware.network` entry in `vm.json`:

```json
{"card": "rtl8029-pci", "port": "300", "mode": "none"}
```

The card occupies PCI 00:05.0, identifies as 10EC:8029 and has a 32-byte
I/O BAR. Its initial port is 0300h unless configured otherwise. PCI INTA
uses PIRQD, routed by the motherboard; the entry's ISA IRQ setting does
not route this card. The full 32-bit BAR is retained, so an address above
the x86 I/O space cannot alias into low ports. Disabled or colliding BARs
do not decode I/O. Bus mastering is not supported by this chip.

One ISA NE2000 and one RTL8029 may coexist at distinct initial ports. Two
RTL8029 cards are rejected because the current snapshot registry has one
section per card model. USB retains its own PCI functions. The legacy
`Machine.Network` service refers to the first configured network card;
its underlying PCI core has internal base and IRQ zero, not guest resources.

Drivers reach packet RAM through remote DMA at offsets 10h–17h. Word and
dword accesses use the core's word-transfer path. The existing doubled
PROM backing is preserved: Linux's DCR=49h byte-read probe consumes two
backing bytes per read and obtains the first six MAC octets directly.
This compatibility sequence is not a physical oracle for every possible
PROM width/count combination.

Page three supplies the Realtek IDs and configuration registers. EEM=11
unlocks CONFIG2/3; EEM=01 synchronously reloads the synthetic EEPROM and
returns the command register to 21h. Local reset aliases preserve PCI and
page-three configuration; machine reset restores the synthetic defaults.
There is no serial EEPROM command engine or reload timing model.

Full duplex, flow control, sleep, power down and clock controls are stored
configuration only. They do not change packet timing, process pause frames,
gate reception or halt register access. EEPROM programming mode likewise
does not suppress DMA. Existing NE2000 filtering, packet and page-two
simplifications remain. Windows driver compatibility has not been verified.

Snapshots store the existing NE2000 version-one payload plus four Realtek
configuration bytes in `R829` version one. PCI configuration remains in the
machine's PCI section and restores before the card. Invalid embedded ISA
identity or configuration bits are rejected before machine RAM changes.
The target machine keeps its network backend; pending remote DMA and the
interrupt level resume from the saved device state.

The register contract follows the [Realtek RTL8029AS data sheet, LS009.0](https://bitsavers.org/components/realtek/RTL8029S_199701.pdf).
The PROM probe and duplex sequence were checked against the
[Linux ne2k-pci driver](https://github.com/torvalds/linux/blob/master/drivers/net/ethernet/8390/ne2k-pci.c).
